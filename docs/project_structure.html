survey-features — codebase structure

Does an LLM know, from prior knowledge alone, which respondent characteristics predict how someone answers a given survey question — and does that reasoning adapt across countries? Six surveys (WVS, ESS waves 10–11, and the Afro/Arab/Asian/Latino barometers), graded against an AutoGluon permutation-importance oracle.

Restructured in commit 472e418 — “Restructure into installable survey_features package with free-text as the main pipeline.” Two things changed at once:
  • Layout. All pipeline logic moved into an installable package at src/survey_features/ (pip install -e .). scripts/ now holds thin entry points only; findings moved to docs/; dead code moved to archive/. The old flat phase0b_*.py modules are gone.
  • Method. Free-text elicitation is now the main pipeline — pilot 2 found that demanding JSON suppresses selection breadth. The JSON grid is demoted to a legacy appendix path, and a new extraction step (fixed Qwen-235B) turns essays into typed feature lists so both formats share an identical downstream path.
The framing: an AutoGluon oracle computes the ground-truth feature ranking from the microdata (the answer key); the selector LLM nominates features from prior knowledge alone (the student with no notes). Both sets — plus a matched-size random baseline — are scored with XGBoost cross-validation.
captured_importance  ·  value_over_random = model_acc − random_acc  ·  cost_of_imperfect = oracle_acc − model_acc

src/survey_features/ — the shared library13 modules · 2,557 lines
All pipeline logic, one copy each. If two scripts need the same function it belongs here — see CONTRIBUTING.md. Most modules carry both a current (free-text) and a legacy (JSON) path.
  • __init__.py19The module map in pipeline order — the orientation doc for the whole package. Version 0.1.0.
  • config.py47Repo-root resolution (SURVEY_FEATURES_ROOT), .env loading, and the model registry: SELECTORS (deepseek, kimi — the models under test), the fixed EXTRACTOR_MODEL, DISAMBIGUATORS (nemotron, qwen235b), the two CONDITIONS, and PIPE_TYPES (which feature types enter scoring).
  • surveys.py216Survey loading, per-survey country columns, metadata handling — the single copy, previously duplicated between the grid runner and the oracle.
  • llm.py199The one OpenAI-compatible client used everywhere. Linear-backoff retries on 429s/5xx/provider hiccups so a flaky call can’t abort a long sweep; per-request token-usage logging. Works with SGLang, OpenRouter, OpenAI, Nebius, Together.
  • prompts.py72Every prompt template in one place. The free-text prompts are the exact JSON prompts with only the formatting block removed — nothing added, nothing rephrased — which is what isolates the format effect.
  • elicitation.py161Selection calls. Current: freetext_messages, essay cached verbatim. Legacy: run_single/run_batch demanding strict JSON.
  • extraction.py66One call to a fixed capable extractor turns a raw response into a typed feature list. The point: JSON and free-text arms then travel an identical downstream path, so the only difference between them is the selection format.
  • retrieval.py218Sentence-transformer + survey-variable embedding caches. Dual-embed: each feature is embedded twice (label-only and “label: context”), similarity is the max — stops reasoning text from dragging short labels like “age” into the target’s topic domain. Current: per-feature top-20. Legacy: batch top-5.
  • disambig.py281Maps each requested feature to exactly one survey code or “none”, one question per feature. Diagnostics showed per-feature retrieval is far sharper than whole-response retrieval (query similarity ~0.7 vs ~0.38). Mapping is one-to-one; bundled sub-items are recorded for auditing only.
  • oracle.py742The AutoGluon permutation-importance oracle — the largest module. Feature-pool construction, semantic near-duplicate filtering, missingness handling, quick/balanced/best runtime modes. Requires the [oracle] extra; everything else runs off the cached CSVs.
  • evaluation.py241Matched-k XGBoost 5-fold CV comparing oracle / model-selected / random feature sets. Shared by both the free-text pipeline and the legacy grid.
  • metrics.py119The single copy of the metric arithmetic — previously triplicated across three analysis scripts. Captured importance, Jaccard, oracle percentile, adaptation score, cluster bootstrap.
  • layout.py176The outputs/ path contract: per-model LLM caches, grid-summary naming and discovery, format-pilot directories. Load-bearing — existing cached runs must keep resolving.
scripts/ — entry points3 files · 1,468 lines
Thin orchestration only; no analytics logic.
  • run_main.py398Canonical entry point. The free-text pipeline in four resumable phases — gen → extract → map → score — over the genuine cells, per selector. Every phase checkpoints per cell (--force recomputes, --limit N smoke-tests). Generalised from the old analysis/format_pilot.py, with artifact paths unchanged so pilot-2 results stay valid.
  • run_grid.py775The legacy pilot-1 JSON grid, kept runnable so the paper’s appendix stays reproducible. Same five steps as before the restructure, same artifact paths, now a thin wrapper over the package. Flags: --survey --targets --countries --from-manifest --run-tag --stop-after --grid-workers.
  • leakage_audit.py295Phase B1. Flags cells whose oracle top feature is a label-in-disguise (importance concentration + a semantic check the oracle’s own cosine filter misses because the wordings aren’t lexically similar). Defines the genuine-cell set the main experiment runs on.
